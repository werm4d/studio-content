THE CAMPAIGN · BUILDER'S REFERENCE

Claude File Types Field Card

A plain-language guide to the file formats Claude produces — what each one is, why you'd reach for it, and where it falls short. Aimed at a working-but-not-expert coder. Knowing which format fits the job is half of getting a clean result the first time.

Pick the right container for the job
00 — TWO BIG QUESTIONS
Before the formats: how Claude hands you a file

Every file Claude makes lands in one of two ways, and knowing which saves confusion. Some render live in the chat — you see the result immediately. Others are downloadable files you save and open elsewhere. The format determines which.

▦ Renders in chat (Artifact)

Code that the chat window can run or display on the spot — a webpage, an interactive tool, a chart, a formatted document preview. You see it working without leaving the conversation. Great for "show me" and for iterating fast.

↓ Downloadable file

A real file written to disk that you download and open in its own program — Word, Excel, a PDF reader, your code editor. This is how you get something you can keep, send, or deploy. Most of your APEX/Campaign deliverables are these.

The mental model: an artifact is a live preview; a downloadable file is the thing you own. Some formats can be both (an HTML page renders and downloads). Throughout this card, a green RENDERS badge means it previews live; a orange DOWNLOAD badge means you save it to open elsewhere.

01 — THE LIVE ONES
Web & interactive formats

These render right in the chat, which is why every dashboard and reference card in your toolkit is one of them. They're also self-contained — a single file you can host anywhere, no install required.

.html HTML pageHyperText Markup Language — a web page ● RENDERS + DOWNLOADS
What it is
The language of web pages. One file can hold the structure, styling (CSS), and behavior (JavaScript) all together — a complete, standalone app.
Why use it
Self-contained and runs in any browser with zero setup. Perfect for dashboards and tools you host yourself. Your APEX Terminal and these field cards are single HTML files.
Limitations
Can't save data on its own between sessions unless wired to storage. Not ideal for heavy number-crunching or large datasets.
.jsx React componentJavaScript + markup — interactive UI ● RENDERS
What it is
A way to build interactive interfaces in pieces ("components") that update themselves as data changes. The Campaign engine is a React file.
Why use it
Best for tools with state — things that remember inputs, track lists, recalculate live. Cleaner than raw HTML once a tool gets complex.
Limitations
Needs a React environment to run outside the chat (more setup than plain HTML). Steeper learning curve. Overkill for a static page.
.svg Vector graphicScalable Vector Graphics — math-drawn images ● RENDERS
What it is
An image defined by shapes and coordinates rather than pixels — so it stays razor-sharp at any size. The payoff diagrams on your options cards are SVG.
Why use it
Crisp at any zoom, tiny file size, and editable as text. Ideal for diagrams, charts, logos, and icons.
Limitations
Wrong tool for photographs or richly detailed images. Complex SVGs can get verbose and slow.
02 — THE WORKHORSES
Code & scripts

These are instructions for a computer to execute. They don't "render" — they run, doing work: fetching data, crunching numbers, automating a task, or generating other files. Your TRIDENT bot and PDF generators live here.

.py Python scriptGeneral-purpose programming language ● DOWNLOAD / RUN
What it is
A readable, widely-used programming language. Runs on your machine to do almost anything — call APIs, process data, automate trades, build PDFs (your ReportLab scripts).
Why use it
The Swiss-army knife. Huge library ecosystem, gentle syntax, ideal for automation and data work. Your TRIDENT Automator and Forex Compounder are Python.
Limitations
Needs Python installed to run. Not for in-browser interfaces. Slower than compiled languages for extreme performance (rarely matters here).
.bat Batch fileWindows command script ● DOWNLOAD / RUN
What it is
A short list of Windows commands that run in sequence when you double-click it. Your START_APEX.bat launcher is one — one click instead of typing commands.
Why use it
Removes friction. Turns a multi-step terminal routine (start the server, open the browser) into a single double-click. Great for repeated tasks.
Limitations
Windows-only. Limited logic — fine for launching things, not for real programs. Python is better once there's any complexity.
.ts script ThinkScriptThinkorSwim's built-in language ● PASTE INTO TOS
What it is
A specialized language that runs inside ThinkorSwim to draw indicators, color bars, and scan for setups. Your TRIDENT and Double Helix studies are ThinkScript.
Why use it
The only way to express custom signals natively in TOS. Lives in the platform — no external server, runs on every chart and scan automatically.
Limitations
Locked to the ThinkorSwim platform — can't run anywhere else. Can't place trades on its own (alerts/visuals only).
03 — THE DELIVERABLES
Document formats

Formats built for reading, printing, and sharing with people — not computers. The right choice depends on whether you need easy editing, fixed layout, or lightweight plain text.

.docx Word documentMicrosoft Word format ● DOWNLOAD
What it is
The standard editable document — headings, tables, styles, page numbers. Your operator's manual and quick-reference card are docx.
Why use it
When someone needs to edit it, or expects a "real" professional document. Universally accepted for formal deliverables and proposals.
Limitations
Layout can shift slightly between Word, Google Docs, and Mac. Heavier to produce than plain text. Overkill for quick notes.
.pdf PDFPortable Document Format — fixed layout ● DOWNLOAD
What it is
A document that looks identical everywhere — every font, margin, and image locked in place. Your ReportLab nutrition guides are print-ready PDFs.
Why use it
When layout must not move — print-ready material, official documents, anything where "it looks right on my screen" must hold for everyone.
Limitations
Hard to edit after the fact (it's meant to be final). Reflowing text or fixing a typo often means regenerating from the source.
.md MarkdownPlain text with simple formatting ● RENDERS + DOWNLOADS
What it is
Plain text that uses simple marks (# for headings, * for bullets) to add light formatting. Readable raw or rendered pretty. Your DoubleHelix package is .md.
Why use it
Fast, future-proof, and version-control friendly. Ideal for notes, READMEs, and documentation that lives near code. Opens in anything.
Limitations
Limited formatting — no precise layout, page control, or complex tables. Not for polished client-facing deliverables.
04 — THE DATA HOLDERS
Data & spreadsheet formats

Formats whose job is to hold structured information — rows, columns, records — so people or programs can work with it. The split here is human-facing (Excel) versus machine-facing (CSV, JSON).

.xlsx Excel spreadsheetMicrosoft Excel format ● DOWNLOAD
What it is
A full spreadsheet — multiple sheets, live formulas, charts, formatting. Your Project Jessup pro forma (9 sheets, 800+ formulas) is xlsx.
Why use it
When you need calculations, models, or financial analysis a person will open and tweak. Formulas recalculate live — ideal for pro formas and trackers.
Limitations
Heavier than raw data formats. Not ideal as a data feed between programs (use CSV/JSON for that). Can get fragile with very complex formula webs.
.csv CSVComma-Separated Values — a plain table ● DOWNLOAD
What it is
The simplest possible table: plain text, one row per line, columns split by commas. Every spreadsheet and data tool on earth reads it.
Why use it
The universal handoff format. Exporting trade logs, importing into a tool, moving data between programs — CSV is the lowest common denominator that always works.
Limitations
No formulas, formatting, or multiple sheets — just raw values. No way to store nested or hierarchical data.
.json JSONJavaScript Object Notation — structured data ● DOWNLOAD / CONFIG
What it is
A text format for structured data using labeled fields and nesting — like a labeled filing system. Your TRIDENT bot reads/writes trident_state.json.
Why use it
The standard way programs exchange data and store settings. Handles nested structure CSV can't. Most APIs speak JSON.
Limitations
Meant for machines, not humans — clumsy to read or edit by hand at scale. One misplaced comma or bracket breaks the whole file.
05 — THE QUICK PICK
"I want to…" → use this

When you're not sure what to ask Claude to build, start from the goal. Name what you want to do with the result, and the format usually picks itself.

I want to…UseWhy
Build a tool I can host and use on my phone.htmlSelf-contained, runs in any browser, no install
Build an interactive tool that tracks state.jsxReact handles live inputs, lists, recalculation
Automate a task on my computer.pyPython runs locally, talks to APIs, automates
Send a formal, editable document.docxProfessional, editable, universally expected
Hand someone something print-ready.pdfLooks identical everywhere, layout locked
Write notes or a README near my code.mdLightweight, readable, future-proof
Build a financial model with formulas.xlsxLive formulas, multiple sheets, charts
Move data between two programs.csvUniversal table format everything reads
Store settings or program state.jsonStructured, nestable, what programs expect
Draw a sharp diagram or chart.svgCrisp at any size, tiny, editable as text
One rule that prevents most rework: tell Claude the destination, not just the content. "A report I'll email to a client" → docx. "A report I'll print and pin up" → PDF. "Numbers I'll keep adjusting" → xlsx. "A tool I'll run on my iPad" → HTML. Same content, four different right answers — and the destination is what decides.
